Testing tools

Fabric channel

The channel is created here, not baked into the stack — nothing else on this page (chaincode queries, peer sync) works until a channel exists. This orderer uses Fabric's channel participation API (osnadmin), so creating a channel means: generate its genesis block from network_config.yaml, join it to the orderer, join both hospital peers, then update both orgs' anchor peers — all four steps run in order below. Safe to re-run for a channel that already exists.

Key management

Name your own key — not limited to Hospital_A/Hospital_B. This generates a Falcon-1024 + Kyber-512 keypair under whatever name you give it (a device, a test identity, anything). It does not by itself add a new org to the Fabric network — that's a bigger change (network_config.yaml + quantum_cryptogen.py).

Test: peer-to-peer ledger sync (Hospital A ↔ Hospital B)

Asks each hospital's peer directly — not through the shared cli helper — for its own view of the channel. If both report the same block height, Fabric's gossip/replication protocol has actually converged both peers on the same ledger, not just "both containers are running".

Test: MQTT publish

Publishes to the plain mqtt broker as a connectivity smoke test (does not go through the quantum encryption layer — that needs org keys present, see Key management above).

Fabric chaincode

Package, install (on both peers), approve (by both orgs), and commit a chaincode on the channel above — nothing below this is queryable until this has run at least once per channel. Safe to re-run for the same version/sequence.

Ops Agent checking…

agents/ops_agent · real, deployed — a standalone script that calls the Anthropic API directly (not through this dashboard or Cowork) to watch this docker-compose stack via /api/ops/* and decide whether to notify a human or bring a stuck service back up.
Policy: never acts on the first sighting of a problem, only notifies. Only ever autofixes a service stuck in "Created" (a docker compose up that never finished) after seeing it persist across a run. Never auto-restarts a crashing/exited container, and has no tool that can stop or remove anything.

"Run check now" makes a real call to the Anthropic API — same as running python3 -m agents.ops_agent.agent --check from a terminal — so it can take up to ~30s and isn't free. This hourly check also runs on its own via a scheduled task outside this page.

Guidance for the agent

Notes left here get folded into the agent's context on its next run — e.g. "hedera-bridge exiting 0 is expected, don't flag it" as a standing (sticky) note, or "keep an eye on asterisk after today's fix" as a one-time nudge. One-time notes are consumed after a single run; sticky notes stay until removed.
